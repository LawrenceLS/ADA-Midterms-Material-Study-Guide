Part A — Rapid Recap

0Asymptotic Notation

O = "at most" (upper bound), Ω = "at least" (lower bound), Θ = "exactly" (both, tight). Drop constants and lower-order terms. Growth order best→worst: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!). "Case" (best/worst/avg) and "symbol" (O/Ω/Θ) are independent axes.

1Divide and Conquer

Divide → Conquer (recurse) → Combine. Analyse with T(n)=a·T(n/b)+f(n). Master Theorem: let c=log_b a; compare f(n) vs n^c: slower→Θ(n^c) [Case 1, leaves win]; equal→Θ(n^c log n) [Case 2]; faster→Θ(f(n)) [Case 3, root wins]. Recursion tree = work-per-level × #levels.

2Time & Space Complexity

Time = how operations grow. Space = extra memory = auxiliary structures + max recursion-stack depth. Time ≠ space (e.g. recursive Fibonacci is O(2ⁿ) time but O(n) space).

3Amortized Analysis

Average cost per operation over a whole sequence (not probability). Aggregate: total ÷ n. Accounting: assign a constant charge, store surplus as credit, keep credit ≥ 0. Potential: energy function Φ. Dynamic array append = O(1) amortized.

4Randomized Algorithms

Random choices defend against adversarial inputs. E[X]=Σ value·prob. Linearity: E[ΣXᵢ]=ΣE[Xᵢ] (always). Geometric: expected trials to first success = 1/p. Randomized Quick Sort = expected O(n log n). Las Vegas (always correct, random time) vs Monte Carlo (fixed time, maybe wrong).

5Greedy Algorithms

Take the locally best choice, never reconsider. Correct only if greedy choice property (local choice is safe) + optimal substructure hold. Prove with the exchange argument; disprove with one counterexample. Activity Selection (earliest finish) works; coin change {1,3,4} fails.

Part C — Mixed Exam

20 questions spanning every topic, in random order (like a real exam). Attempt each, then click 🔒 Reveal answer.

1Solve T(n) = 2T(n/2) + n and name an algorithm with this recurrence. D&C

Reveal answer

c=log₂2=1, f(n)=n=n^c → Case 2 → Θ(n log n). Algorithm: Merge Sort (or D&C max-subarray).

2What does it mean that Big-O is "only an upper bound"? Give an example of a true-but-useless Big-O statement. Notation

Reveal answer

Big-O gives a ceiling, not an exact rate — a slower-growing function can have many valid (looser) ceilings. True-but-useless: "Merge Sort is O(n!)" — technically correct (n! is a valid ceiling) but unhelpful; the tight answer is Θ(n log n).

3Using the aggregate method, show the amortized cost of append on a doubling array is O(1). Amortized

Reveal answer

n writes cost n. Resizes at 1,2,4,…,n copy a total of ~2n. Total = 3n. Divide by n → 3 → O(1) amortized.

4A greedy makes change with coins {1,3,4} for amount 6. Does it find the optimal solution? Greedy

Reveal answer

No. Greedy: 4+1+1 = 3 coins. Optimal: 3+3 = 2 coins. One counterexample disproves greedy for this coin system.

5Flip a fair coin until heads. Expected number of flips? Randomized

Reveal answer

Geometric with p=1/2 → E=1/p=2.

6Solve T(n) = T(n/2) + 1. What algorithm is it? D&C

Reveal answer

c=log₂1=0, n^c=1=f(n) → Case 2 → Θ(log n). Algorithm: Binary Search.

7Recursive Fibonacci is O(2ⁿ) time. What is its space complexity, and why isn't it also O(2ⁿ)? Space

Reveal answer

O(n). Space = max stack depth, not total calls. The two recursive calls run sequentially, so only one branch (depth ≤ n) is on the stack at a time.

8Write the expected-time recurrence for randomized Quick Sort and give the result. Randomized

Reveal answer

E[T(n)] = 2·E[T(n/2)] + O(n) → Case 2 → O(n log n).

9State the two properties a greedy algorithm needs to be correct. Greedy

Reveal answer

Greedy choice property (local optimal choice is safe / leads to a global optimum) and optimal substructure (remaining problem is a smaller instance of the same problem).

10Solve T(n) = 3T(n/2) + n (Karatsuba). D&C

Reveal answer

c=log₂3≈1.585, f(n)=n < n^1.585 → Case 1 → Θ(n^1.585).

11Accounting method: what charge per push makes a stack with multipop O(1) amortized, and where is credit stored? Amortized

Reveal answer

Charge 2 per push: 1 pays the push, 1 is stored on the element to prepay its pop. Multipop charged 0, paid by stored credit. Credit never negative → O(1) amortized.

12n people get hats back at random. Expected number who get their own hat? Which technique? Randomized

Reveal answer

Linearity of expectation with indicators: Pr[person i own hat]=1/n, so E = n·(1/n) = 1.

13Is Quick Sort's worst case O(n²) or Θ(n²)? Explain the difference in this context. Notation

Reveal answer

Both are correct for the worst case. Θ(n²) is the tight claim: a bad input (e.g. sorted, with fixed pivot) really achieves ~n² operations. O(n²) just states the ceiling. People usually say "O(n²)" as a worst-case guarantee.

14Give the time AND space complexity of Merge Sort; explain the space. Space

Reveal answer

Time Θ(n log n). Space O(n) — the merge step allocates a temp array of size up to n (dominates the O(log n) recursion stack).

15Recursion tree: for T(n)=4T(n/2)+n, does work per level increase, stay constant, or decrease, and what's the result? D&C

Reveal answer

Level i work = 4ⁱ·n/2ⁱ = n·2ⁱ → increases → leaves dominate. At leaf level (i=log₂n): n·2^(log₂n)=n². Result Θ(n²).

16Classify as Las Vegas or Monte Carlo: (a) randomized Quick Sort, (b) a primality test with a 1% false-positive rate. Randomized

Reveal answer

(a) Las Vegas — always correct, random time. (b) Monte Carlo — fixed time, possibly wrong.

17A greedy for Activity Selection picks the earliest-FINISHING activity. Sketch the exchange argument that this is safe. Greedy

Reveal answer

Let g finish earliest overall, and o be the first activity in some optimal solution OPT. Since g.finish ≤ o.finish, swapping o for g keeps all later activities compatible and preserves the count. So an optimal solution containing g exists → the greedy choice is safe. Repeat on the remainder. ∎

18Increment a binary counter n times. Total bit flips and amortized cost per increment? Amortized

Reveal answer

Bit i flips n/2ⁱ times; total = n+n/2+n/4+… < 2n. Amortized = <2n/n = 2 → O(1) per increment.

19Why does using a RANDOM pivot help Quick Sort, given the worst case is still O(n²)? Randomized

Reveal answer

With a fixed pivot an adversary (or just a sorted input) can always trigger O(n²). A random pivot means no specific input can reliably force the worst case — the worst case still exists but is astronomically unlikely, so the expected time is O(n log n).

20Rank these by growth, slowest to fastest: n², log n, n log n, 2ⁿ, n, 1, n!. Notation

Reveal answer

1 < log n < n < n log n < n² < 2ⁿ < n!
