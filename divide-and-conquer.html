1. The Core Idea

Divide and Conquer (D&C) solves a problem by breaking it into smaller versions of itself, solving those, then stitching the answers together. Three steps:

  1. Divide — split the input into smaller sub-problems (usually equal halves).
  2. Conquer — solve each sub-problem recursively (the base case stops the recursion).
  3. Combine — merge the sub-answers into the final answer.

To analyse the running time, express it as a recurrence and solve with the Master Theorem or a recursion tree:

T(n) = a · T(n/b) + f(n)
  a    = number of sub-problems
  n/b  = size of each sub-problem
  f(n) = divide + combine work (outside the recursion)

Critical exponent:  c = log_b(a)
  Case 1: f(n) < n^c   →  T(n) = Θ(n^c)          (leaves dominate)
  Case 2: f(n) = n^c   →  T(n) = Θ(n^c · log n)   (every level equal)
  Case 3: f(n) > n^c   →  T(n) = Θ(f(n))          (top work dominates)
Classic D&C algorithms: Merge Sort, Quick Sort, Binary Search, Karatsuba multiplication, Strassen matrix multiply, Closest Pair of Points, Maximum Subarray.

2. Worked Examples

Example 1 — Merge Sort (the canonical D&C sort)

MergeSort(A):
    if length(A) <= 1: return A            # base case
    mid   = length(A) / 2
    left  = MergeSort(A[0 .. mid])         # divide + conquer (n/2)
    right = MergeSort(A[mid .. end])       # divide + conquer (n/2)
    return Merge(left, right)              # combine = O(n)
Step 1 — Map to the template. 2 sub-problems (a=2), each half-size (b=2), merging is one linear pass (f(n)=n). → T(n) = 2T(n/2) + n.
Step 2 — Critical exponent. c = log₂2 = 1, so n^c = n.
Step 3 — Compare. f(n)=n = n^c → tie → Case 2.
Step 4 — Answer. Time = Θ(n log n). Space = O(n) (temp merge array) + O(log n) stack → O(n).

Example 2 — Why it's n log n, seen as a recursion tree

Level 0: n → n / \ Level 1: n/2 n/2 → n/2 + n/2 = n / \ / \ Level 2: n/4 n/4 n/4 n/4 → 4·(n/4) = n ... Leaves: n nodes of size 1 → n work per level = n · number of levels = log₂n = n log n

Each level sums to exactly n (twice as many nodes, each doing half the work — cancels). There are log₂n levels. Product = Θ(n log n).

Example 3 — Binary Search

BinarySearch(A, target, lo, hi):
    if lo > hi: return NOT_FOUND
    mid = (lo + hi) / 2
    if A[mid] == target: return mid
    if A[mid] < target:  return BinarySearch(A, target, mid+1, hi)
    else:                return BinarySearch(A, target, lo, mid-1)
Step 1. Only ONE half is searched (a=1), it's half-size (b=2), work is a single comparison (f(n)=1). → T(n) = T(n/2) + 1.
Step 2. c = log₂1 = 0 → n^c = n⁰ = 1.
Step 3. f(n)=1 = n^c → Case 2.
Step 4. Time = Θ(log n). Space = O(log n) recursive / O(1) iterative.

Example 4 — Maximum Subarray (D&C version)

Find the contiguous subarray with the largest sum. D&C idea: the best subarray lies entirely in the left half, entirely in the right half, OR crosses the midpoint.

MaxSubarray(A, lo, hi):
    if lo == hi: return A[lo]                    # base case
    mid = (lo + hi) / 2
    L = MaxSubarray(A, lo, mid)                  # best in left   (n/2)
    R = MaxSubarray(A, mid+1, hi)                # best in right  (n/2)
    C = MaxCrossingSum(A, lo, mid, hi)           # best crossing  O(n)
    return max(L, R, C)
Step 1. 2 sub-problems (a=2), half-size (b=2); the crossing scan is linear (f(n)=n). → T(n) = 2T(n/2) + n.
Step 2–3. Same shape as Merge Sort: c=1, f(n)=n=n^c → Case 2.
Step 4. Time = Θ(n log n). (Kadane's algorithm later does this in O(n), but this is the clean D&C version.)

Example 5 — Karatsuba fast multiplication

Multiplying two n-digit numbers. Naive = O(n²). Karatsuba splits each number in half and cleverly uses only 3 recursive multiplications instead of 4.

Step 1. 3 sub-problems (a=3), each half the digits (b=2), with O(n) additions/shifts to combine (f(n)=n). → T(n) = 3T(n/2) + n.
Step 2. c = log₂3 ≈ 1.585 → n^c = n^1.585.
Step 3. f(n)=n = n¹ < n^1.585 → Case 1 (leaves dominate).
Step 4. Time = Θ(n^1.585) — faster than naive O(n²). This is the payoff of using fewer sub-problems.
💡 Pattern to notice: reducing a (fewer recursive calls) lowers the exponent c = log_b a and can turn O(n²) into something sub-quadratic. That's the whole trick behind Karatsuba and Strassen.

3. Practice Questions

Try each on paper, then click 🔒 Reveal answer. Focus on the method: identify a, b, f(n), find c, compare, conclude.

1An algorithm splits the input into 2 halves and does O(1) combine work. Write the recurrence and solve it. Master

Reveal answer

a=2, b=2, f(n)=1 → T(n) = 2T(n/2) + 1.

c = log₂2 = 1, n^c = n. Compare f(n)=1 < n → Case 1 (leaves dominate).

T(n) = Θ(n).

Intuition: a full binary recursion tree with n leaves already has ~n nodes, so even O(1) work each totals O(n). (This is why "tree traversal" style D&C is linear.)

2Solve T(n) = 7T(n/2) + n² (this is Strassen's matrix multiplication recurrence). Master

Reveal answer

a=7, b=2, f(n)=n². c = log₂7 ≈ 2.807 → n^c ≈ n^2.807.

Compare f(n)=n² < n^2.807 → Case 1.

T(n) = Θ(n^log₂7) ≈ Θ(n^2.807)

— faster than naive matrix multiply's O(n³).

3Use a recursion tree to solve T(n) = 2T(n/2) + n, then state the number of levels and work per level. Recursion Tree

Reveal answer

Work per level is constant at n (level i has 2ⁱ nodes each doing n/2ⁱ work = n). Number of levels until size 1 = log₂n.

Total = n × log₂n.

T(n) = Θ(n log n).

4Here is pseudocode. Identify whether it's divide and conquer, write its recurrence, and give its time complexity. Code → recurrence

Power(x, n):               # compute x^n
    if n == 0: return 1
    half = Power(x, n/2)
    if n is even: return half * half
    else:         return half * half * x
Reveal answer

Yes — it's D&C ("exponentiation by squaring"). It makes ONE recursive call on half the exponent, then O(1) multiplications.

a=1, b=2, f(n)=1 → T(n) = T(n/2) + 1. c = log₂1 = 0, n^c=1, f(n)=1 → Case 2.

Time = Θ(log n)

— far better than the naive O(n) loop of multiplying x by itself n times.

5Solve T(n) = 4T(n/2) + n². (Watch for the tie!) Master

Reveal answer

a=4, b=2, f(n)=n². c = log₂4 = 2 → n^c = n².

Compare f(n)=n² = n² → tie → Case 2.

T(n) = Θ(n² log n).

Contrast: 4T(n/2)+n would be Case 1 → Θ(n²). The combine cost matters!

6Give BOTH the time and space complexity of Merge Sort, and explain the space part specifically. Time + Space

Reveal answer

Time: T(n)=2T(n/2)+n → Θ(n log n).

Space: the Merge step allocates a temporary array of size up to n to hold merged results → O(n) auxiliary. The recursion stack adds O(log n). Dominant term:

Space = O(n).

This is Merge Sort's main weakness vs Quick Sort, which sorts in place with only O(log n) average stack space.

7A buggy "D&C" algorithm splits into 2 halves but then does O(n²) combine work. Solve T(n) = 2T(n/2) + n² and say which part of the cost dominates. Master / Case 3

Reveal answer

a=2, b=2, f(n)=n². c = log₂2 = 1, n^c=n. Compare f(n)=n² > n → Case 3.

T(n) = Θ(n²).

The top-level combine work dominates — the recursion barely matters because the expensive O(n²) combine at the root already costs as much as everything below it combined.

8Binary Search is D&C with a=1. Explain in words why having only ONE sub-problem (instead of two) makes it Θ(log n) rather than Θ(n). Conceptual

Reveal answer

With a=1, each step throws away half the data and recurses on only the surviving half — so the recursion tree is a single path, not a branching tree. Its length is the number of halvings to reach size 1 = log₂n, and each node does O(1) work → Θ(log n).

Merge Sort has a=2: it keeps BOTH halves, so the tree branches and has ~n leaves, forcing at least Θ(n) total work (and Θ(n log n) with the linear merge). The difference between "keep one half" and "keep both halves" is the difference between logarithmic and linear+.
