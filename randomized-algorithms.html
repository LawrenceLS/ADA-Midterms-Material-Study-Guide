1. The Core Idea

A randomized algorithm makes random choices while it runs. The point is to defend against bad inputs: instead of letting an adversary design the one input that triggers our worst case, we scramble our own decisions so that no fixed input can reliably be bad. The running time (or correctness) then becomes a matter of expectation — an average over the algorithm's own coin flips, not over the inputs.

Expected value — the one formula you need

E[X] = Σ (value × probability of that value)

Example: a fair die → E = (1+2+3+4+5+6)/6 = 3.5.

Linearity of expectation (hugely useful): E[X + Y] = E[X] + E[Y] — ALWAYS, even if X and Y are dependent. This lets you break a messy total into simple pieces and add their expectations.
Geometric distribution: if each independent trial succeeds with probability p, the expected number of trials until the first success is 1/p. (Flip a fair coin until heads → 1/(1/2) = 2 flips.)

3. Worked Examples

Example 1 — Randomized Quick Sort

QuickSort(A):
    if length(A) <= 1: return A
    pivot = A[ RANDOM index ]        # <-- the randomization
    left  = elements < pivot
    right = elements > pivot
    return QuickSort(left) + [pivot] + QuickSort(right)
Step 1 — Why randomize? With a fixed pivot (always the first element), a sorted input makes every partition lopsided (n−1 and 0), giving the worst case O(n²). A random pivot means no particular input can force that.
Step 2 — Expected-time recurrence. A random pivot splits roughly in half on average, so E[T(n)] = 2·E[T(n/2)] + O(n) (the O(n) is the partition pass).
Step 3 — Solve it. This is the Merge Sort recurrence: a=2, b=2, f(n)=n, c=log₂2=1, f(n)=n=n^c → Case 2 → E[T(n)] = O(n log n).
Step 4 — Why it holds even with uneven splits. A random pivot gives a split at least as balanced as 1/4 : 3/4 with probability ≥ 1/2. A constant-fraction split keeps the recursion depth O(log n), so with O(n) work per level the expected total stays O(n log n).
On the O-graph: expected case = the O(n log n) curve; the worst case O(n²) sits above it but is astronomically unlikely.

Example 2 — The "number of comparisons" view (indicator variables)

A cleaner proof of Quick Sort's O(n log n) uses indicator random variables.

Step 1. Let X = total comparisons. Define Xij = 1 if elements of rank i and j are ever compared, else 0. Then X = Σ Xij.
Step 2 — Linearity. E[X] = Σ E[Xij] = Σ Pr[i and j compared].
Step 3 — The probability. Ranks i and j are compared iff one of them is the first pivot chosen from the range between them (j−i+1 elements). That probability is 2/(j−i+1).
Step 4 — Sum. E[X] = Σ 2/(j−i+1) which is a sum of harmonic series terms → O(n log n). ∎

Example 3 — Randomized version of Binary Search

Standard Binary Search is deterministic O(log n) (always halves). A randomized variant picks a random split point instead of the exact middle.

Step 1. Each step still discards, on average, a constant fraction of the array (a random pivot removes ~half the range in expectation).
Step 2. Expected recurrence is still E[T(n)] = E[T(fraction·n)] + O(1) with a constant fraction < 1 → O(log n) expected.
Lesson: randomization doesn't always speed things up — here it stays logarithmic. It's mainly a tool to avoid worst cases, not a magic speed boost.

Example 4 — "Modify and prove" (what exams ask)

Modify: take a deterministic algorithm and inject a random choice (e.g., replace "pivot = first element" with "pivot = random element").
Prove: write E[T(n)] as a recurrence (or via indicator variables) and solve it to show O(n log n) expected.
Estimate: match the result to the matching curve on the Big-O graph (O(n log n) for the expected case).

4. Practice Questions

Try each yourself, then click 🔒 Reveal answer. Use the expected-value formula, linearity, or the geometric-distribution fact where helpful.

1You roll a fair six-sided die. What is the expected value of the outcome? Show the calculation. Expected value

Reveal answer

E[X] = Σ value × probability = (1+2+3+4+5+6) × (1/6) = 21/6 = 3.5.

Expected value = 3.5.

2You roll a die repeatedly until you get a 6. What is the expected number of rolls? Geometric

Reveal answer

Each roll succeeds (gets a 6) with probability p = 1/6. For a geometric distribution the expected number of trials until first success is 1/p.

E = 1 / (1/6) = 6 rolls.

3Explain why deterministic Quick Sort (pivot = first element) is O(n²) on an already-sorted array, and how a random pivot fixes it. Reasoning

Reveal answer

Sorted input [1,2,3,4,5], pivot = first (1): everything is larger, so left=[], right=[2,3,4,5] — the split is n−1 and 0 (completely unbalanced). The next level repeats with pivot 2, and so on for n levels. Each level does O(n) partition work → n × n = O(n²). Recurrence T(n)=T(n−1)+O(n)=O(n²).

Random pivot fix: the pivot is now a random element, so on average it lands near the middle and gives a balanced split. No specific input can force lopsided splits because the choice is random, not positional → expected O(n log n).

4Write the recurrence for the expected running time of randomized Quick Sort and solve it with the Master Theorem. Proof

Reveal answer

With a random pivot the expected split is balanced: E[T(n)] = 2·E[T(n/2)] + O(n).

Master Theorem: a=2, b=2, f(n)=n, c=log₂2=1, n^c=n, f(n)=n=n^c → Case 2.

E[T(n)] = O(n log n).

5In randomized Quick Sort, what's the probability that two specific elements of ranks i and j (i < j) are ever directly compared? Indicator variables

Reveal answer

Consider the j − i + 1 elements whose ranks lie between i and j (inclusive). Elements i and j are compared if and only if one of them is the FIRST of this whole group to be chosen as a pivot. (If some middle element is picked first, i and j get separated into different partitions and never compared.)

Each of the j − i + 1 elements is equally likely to be picked first, and 2 of them (i and j) cause a comparison →

Pr[i and j compared] = 2 / (j − i + 1).

6Classify each as Las Vegas or Monte Carlo: (a) randomized Quick Sort, (b) a primality test that may call a composite "prime" with probability 1%, (c) picking a random array index and returning that element as an "approximate median." Classify

Reveal answer
  • (a) Las Vegas — always sorts correctly; only the running time is random.
  • (b) Monte Carlo — fixed running time, but the answer can be wrong with small probability.
  • (c) Monte Carlo — fast and fixed-time, but the returned element may not actually be the median.

Rule: Las Vegas gambles on time, Monte Carlo gambles on correctness.

7Using linearity of expectation: n people randomly swap name tags (a uniformly random permutation). What is the expected number of people who end up with their OWN tag? Linearity

Reveal answer

Let Xi = 1 if person i gets their own tag. In a uniform random permutation, Pr[Xi=1] = 1/n (their tag is equally likely to be any of the n positions).

By linearity: E[total] = Σ E[Xi] = n × (1/n) = 1.

Neat result: regardless of how many people, on average exactly 1 person keeps their own tag. (This is the classic "fixed points of a random permutation" fact.)
