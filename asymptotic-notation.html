1. The Big Idea

Asymptotic notation describes how a function grows as n → ∞. We don't care about exact operation counts or constant factors — we care about the shape of growth for large inputs. Why?

  • Constants don't matter at scale. An algorithm doing 100n operations and one doing 3n operations both scale linearly — double the input, double the work. We call both O(n).
  • Small inputs don't matter. For tiny n almost anything is fast; the interesting question is behaviour as n gets large.

Think of these symbols as comparison operators for growth rates — like ≤, ≥, =, but for how fast functions grow.

2. The Five Symbols

SymbolNameAnalogyMeaning (as n→∞)
O(f)Big-O≤Upper bound — grows no faster than f
Ω(f)Big-Omega≥Lower bound — grows at least as fast as f
Θ(f)Big-Theta=Tight bound — grows exactly like f (O and Ω)
o(f)little-o<Strictly slower than f
ω(f)little-omega>Strictly faster than f

The three you need most are O, Ω, Θ. Here's each one carefully.

Big-O — the ceiling (upper bound)

T(n) = O(f(n)) means: past some point, T(n) stays at or below a constant multiple of f(n).

∃ c > 0, n₀ ≥ 0  such that  T(n) ≤ c·f(n)   for all n ≥ n₀
  • The c lets us ignore constant factors (3n and 100n are both O(n)).
  • The n₀ lets us ignore small inputs (we only care about large n).
  • Only an upper bound. 3n² = O(n²) ✅ — but 3n² = O(n³) and even 3n² = O(2ⁿ) are also technically true, because those are valid ceilings. Big-O says "no worse than," not "exactly."

Big-Omega — the floor (lower bound)

T(n) = Ω(f(n)) means: past some point, T(n) stays at or above a constant multiple of f(n).

∃ c > 0, n₀ ≥ 0  such that  T(n) ≥ c·f(n)   for all n ≥ n₀

The mirror image of Big-O. 3n² = Ω(n²) ✅ and also 3n² = Ω(n) (n is a valid floor). Often used to say a problem inherently needs at least some work — e.g. any comparison sort is Ω(n log n).

Big-Theta — the sandwich (tight bound)

T(n) = Θ(f(n)) means T(n) is both O(f(n)) and Ω(f(n)) — f is simultaneously a ceiling and a floor. It grows exactly like f.

∃ c₁, c₂ > 0, n₀  such that  c₁·f(n) ≤ T(n) ≤ c₂·f(n)   for all n ≥ n₀
  • 3n² + 5n = Θ(n²) ✅ — for large n it's squeezed between, say, 1·n² and 4·n².
  • 3n² = Θ(n³) ❌ — n³ is a valid ceiling but NOT a valid floor (3n² drops below any c·n³).
🧩 Core relationship: Θ(f) = O(f) AND Ω(f). Theta is the strongest, most precise claim — it pins the growth rate down from both sides.

3. Why Does Time Complexity Use Θ or O?

This trips everyone up. There are two separate reasons, and the confusion comes from mixing up two independent ideas.

Reason 1 — O is a weaker claim, Θ is stronger

Θ(n log n) says the growth is pinned exactly. O(n log n) only promises no worse than that — it leaves open that it might be faster. When you can prove the tight bound, Θ is more informative. Merge Sort is genuinely Θ(n log n): it always does about n log n work. Saying "O(n log n)" is true but under-sells it.

Reason 2 (the big one) — "case" and "symbol" are INDEPENDENT axes

People confuse two different things:

Axis A — which input scenarioAxis B — which bound symbol
best case / worst case / average caseO / Ω / Θ

These are independent — you can put a Θ on a worst case, or an O on a worst case. Example — Quick Sort:

ScenarioTight (Θ) statementAlso correct
Best caseΘ(n log n)O(n log n), Ω(n log n)
Worst caseΘ(n²)O(n²)
Average caseΘ(n log n)—

So Quick Sort's worst case is Θ(n²) (tight — a bad input really hits n²). Each individual scenario has its own tight Θ bound.

So why does everyone just say "Quick Sort is O(n²)"?

  • Often we only want an upper-bound guarantee for the worst case — "it will never be worse than this." Big-O is the safe, conservative promise, and that's usually what matters in practice.
  • Sometimes we genuinely can't (or don't bother to) prove a tight bound, so O is all we can honestly state.
⚠️ Convention abuse: many textbooks and interviews write "O" when they technically mean "Θ." When someone says "binary search is O(log n)," they almost always mean it's exactly Θ(log n). "O" has become the casual default word for "the complexity." Everyone accepts this slight abuse.

4. The Clean Mental Model

SymbolWordUse it when…
O"at most"You want (or can only prove) an upper-bound guarantee — "no worse than." Perfect for worst-case promises.
Ω"at least"You want a lower-bound guarantee — often "this problem inherently needs at least this much work."
Θ"exactly"You can prove the growth rate precisely (ceiling = floor). The most precise, correct answer.
One-line summary: O = "at most", Ω = "at least", Θ = "exactly". Time complexity often uses O because we mostly care about worst-case guarantees (ceilings), but Θ is the more precise answer whenever the bound is tight — and much of the time when people write O, they actually mean Θ.

5. Practice Questions

Decide the answer yourself, then click 🔒 Reveal answer.

1True or false: 5n² + 3n + 7 = O(n²). Justify with the definition. Big-O

Reveal answer

True. We need c, n₀ with 5n²+3n+7 ≤ c·n². For n ≥ 1, 3n ≤ 3n² and 7 ≤ 7n², so the whole thing ≤ (5+3+7)n² = 15n². Pick c=15, n₀=1. ✓

2Is 5n² = O(n³)? Is 5n² = Θ(n³)? O vs Θ

Reveal answer

5n² = O(n³): True — n³ is a valid ceiling (5n² ≤ 5n³ for n ≥ 1). Big-O only requires an upper bound.

5n² = Θ(n³): False — Θ needs n³ to also be a lower bound, but 5n² eventually falls below any c·n³. So n³ is a ceiling but not a floor → not tight.

3Give the tightest (Θ) bound for T(n) = 3n² + 100n + 500. Θ

Reveal answer

Drop lower-order terms (100n, 500) and the constant factor (3). The dominant term is n².

T(n) = Θ(n²).

For large n it's sandwiched: e.g. 1·n² ≤ T(n) ≤ 4·n² for sufficiently large n.

4Linear search scans an array left to right for a target. State best-case and worst-case time, each with the tightest symbol. Case vs symbol

Reveal answer

Best case (target is the first element): 1 comparison → Θ(1).

Worst case (target absent or last): n comparisons → Θ(n).

Note how "case" (best/worst) and "symbol" (Θ) are independent — each case gets its own tight Θ bound. You could also loosely say the worst case is O(n).

5Someone says "the running time of this algorithm is at least n log n for every input." Which symbol captures that, and what does it mean? Ω

Reveal answer

Ω(n log n) — a lower bound. It means the algorithm never does fewer than a constant times n log n operations, regardless of input. (This is exactly the kind of statement used to prove that any comparison-based sort must take Ω(n log n) — you can't beat it.)

6Why is it technically correct, but unhelpful, to say "Merge Sort is O(n!)"? Conceptual

Reveal answer

It's technically true: n! grows far faster than n log n, so it's a valid (if ridiculously loose) ceiling — Merge Sort certainly never does more than n! work.

But it's unhelpful because Big-O is most useful when it's tight. The informative statement is Θ(n log n), which pins the growth exactly. Saying O(n!) wastes the whole point of the notation — it's like saying "this errand will take at most a year" when it actually takes an hour.

Takeaway: Big-O being "only an upper bound" means you should always aim for the tightest one.

7If T(n) = O(n) and also T(n) = Ω(n), what can you conclude? Relationship

Reveal answer

n is both a ceiling and a floor for T(n) → by definition T(n) = Θ(n).

This is the formal rule: Θ(f) holds exactly when both O(f) and Ω(f) hold.
